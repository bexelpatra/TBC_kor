# 요구사항 (requirements.md)

> 작성: Architect | 다음 에이전트: DB, Backend

## 1. 개요

한국 학원에서 강사가 학생별 특강 내역을 기록하고, 학부모가 **자기 자녀의 기록만** 열람하는 도구.
전체 공지 게시판과, 관리자용 MCP(읽기 전용) 조회 API를 포함한다.

## 2. 액터(Actor)

| 액터 | 설명 | 로그인 방식 |
|---|---|---|
| user (학부모) | 자녀의 특강 기록·공지 열람, 댓글 작성 | 휴대전화 뒷번호(4자리) + 자녀 이름 + 비밀번호(6자리 숫자) |
| admin | 강사 / 보조자 / 관리자 (role) | login_id + 비밀번호(영문·숫자 8자 이상) |

- admin은 `role`(강사 > 보조자 > 관리자, 강사가 최상위)과 `level`(1~10)을 가진다.
- **현재 권한 차등은 적용하지 않음** — 검사 장치(백엔드 의존성 / 프론트 라우트 가드)는 골격만 두고 임계값은 전부 통과.

## 3. 기능 요구사항 (FR)

### FR-1. 로그인
- 로그인 화면 셀렉트 박스로 `user` / `admin` 구분.
- user: 뒷번호 + 이름 + 비밀번호 → 검증. (이름은 HMAC으로 행 조회)
- admin: login_id + 비밀번호.
- 자가 회원가입 없음. user 계정은 관리자가 생성.

### FR-2. 사용자(학생/학부모) 관리 — admin
- 단건 추가(웹 폼) / 수정 / 탈퇴(soft delete).
- **엑셀 일괄 등록**:
  - 다운로드용 양식 제공. 헤더: `뒷번호(학부모)`, `이름`, `번호(4자리)`.
  - 필수값·제약: 뒷번호=숫자 4자리 / 이름 ≤ 20자 / 번호=숫자 4자리(추가 제약 없음).
  - **중복 행(기존 뒷번호+이름)**: 건너뛰고 결과 리포트.
  - **일부 행 오류**: 유효한 행만 등록 + 오류 행 목록 반환.
  - 초기 비밀번호: `00` + 번호 4자리 (예: 0503 → `000503`) → 최초 로그인 시 변경 강제(`must_change_pw`).

### FR-3. 특강 내역
- **데이터 단위**: `lecture`(강의 마스터: 일시·회차·담당 강사) — N:N — `user`, 연결 객체 `lecture_user`(학생별 기록: 제목·내용·이미지·댓글).
- 조회: 게시판/목록, 검색(날짜 범위 + 제목), 페이징(10/20/30 셀렉트), 최신순.
- **user**: 자신의 `lecture_user`만 목록·상세 열람. **다른 학부모의 기록·이미지·댓글은 어떤 경로로도 접근 불가(절대 격리).**
- **admin**: 강의 마스터 및 학생별 기록 작성/읽기/수정/삭제. 한 강의에 여러 학생을 묶어 각자에게 다른 내용·이미지 작성.
- **admin 특강 등록 화면**(프론트): 강의 마스터 입력(일시·주제) → 회차 자동 채번 → 참여 학생 선택 → 학생별 제목·내용·이미지 작성.
- `lecture.round_no`(회차), `notice.serial_no`(일련번호)는 **시스템 자동 채번**(직전 최대값+1).
- 이미지: 게시글당 최대 5장, jpg/jpeg/png, 장당 10MB. 10MB 초과 시 720p(긴 변 1280px) 저화질로 재저장.
- 상세보기: user는 댓글 작성 가능(자기 기록에 한함).
- 댓글: 한 기록에 여러 댓글 가능, 답글은 **1단계만**(관리자 답글). user는 답글 달리기 전까지 자기 댓글 수정/삭제 가능.
- 관리자 **미답변 댓글 모아보기**: 관리자 답글이 아직 없는 user 댓글 인박스.

### FR-4. 전체 공지 게시판
- admin: CRUD. user: 읽기 전용.
- 회차 = 단순 일련번호. 이미지 첨부 가능(특강과 동일 첨부 방식).

### FR-5. MCP API
- **관리자 전용, 읽기 전용.** 특강·공지 조회/검색.
- 인증: 관리자별 API 키(환경변수/DB 저장). 20분 JWT와 별개.

## 4. 비기능 요구사항 (NFR)

| 구분 | 내용 |
|---|---|
| 보안-격리 | 학부모 간 데이터 절대 격리. 조회 쿼리를 `lecture_user.user_id = 본인`으로 강제 스코핑 |
| 보안-암호화 | **user 이름만** AES 암호화 + 조회용 HMAC. admin 이름은 평문(개인정보 아님). 키는 시크릿 |
| 보안-비밀번호 | bcrypt 해시. user=6자리 숫자(초기 `00`+번호 4자리), admin=영문·숫자 혼합 8자 이상 |
| 인증 | JWT, 리프레시 없음. user 20분 / admin 4시간. user·admin 공통 **남은 시간 표시 UI** |
| 저장소 | 파일 저장 로직 추상화(로컬 FS → S3). 경로는 키/상대경로로 저장 |
| 이미지 | 업로드 시 720p 리사이즈/재압축 |
| 시간 | UTC 저장, KST 표시 |
| 삭제 | 전 테이블 soft delete(`deleted_at`) |

## 5. 권한 매트릭스 (현재 시점)

| 기능 | user(학부모) | admin |
|---|---|---|
| 특강 목록/상세 | 본인 기록만 R | 전체 CRUD |
| 특강 댓글 | 본인 기록에 C/U/D(답글 전), 본인 것만 R | 전체 R + 답글 작성 |
| 공지 | R | CRUD |
| 사용자 관리 | — | C/R/U/D + 엑셀 일괄 |
| MCP 조회 | — | R (API 키) |

> role/level별 차등은 추후. 지금은 user/admin 두 역할 기준으로만 분기.
